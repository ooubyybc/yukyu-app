# 有給管理（PWA）

年次有給休暇の **残日数 / 消滅期限 / 付与日数** を自動計算するスマホ用アプリです。
サーバー不要の静的サイトなので、GitHub Pages に置くだけで動きます。

---

## 1. GitHub Pages で公開する手順

**このフォルダ（`yukyu-app`）は、すでに Git リポジトリとして初期化・コミット済みです。**
GitHub Desktop に登録するだけで公開できます。

### 初回だけ

1. GitHub Desktop を開く（未導入なら https://desktop.github.com ／ GitHubアカウントでサインイン）
2. メニュー **File → Add local repository...**（Ctrl+O）
3. **Choose...** で次のフォルダを選ぶ

   ```
   C:\Users\lum4g\OneDrive\デスクトップ\Claude\有給管理表\yukyu-app
   ```

4. **Add repository**
5. 画面中央の **Publish repository** をクリック
6. ダイアログで
   - **Name**: `yukyu`（好きな名前でOK）
   - **Keep this code private のチェックを外す** ← 外さないと GitHub Pages が使えません
7. **Publish repository**
8. メニュー **Repository → View on GitHub**（Ctrl+Shift+G）
9. **Settings → Pages → Source: `Deploy from a branch` / Branch: `main` `/ (root)` → Save**
10. 1〜2分待ってページを再読み込みすると、公開URLが出ます

   ```
   https://<ユーザー名>.github.io/yukyu/
   ```

> 公開されるのはアプリのコードだけで、有給のデータは含まれません（下の「3. データについて」を参照）。
> `有給管理データ.json` は `yukyu-app` の外（親フォルダ）にあるので、コミット対象になりません。

### 2回目以降（ファイルを更新したとき）

1. GitHub Desktop を開くと、左の **Changes** に変更されたファイルが出ています
2. 左下の **Summary** に何を変えたかを短く入力
3. **Commit to main**
4. 上部の **Push origin**

数十秒でサイトに反映されます。スマホ側のキャッシュ対策として、アプリの中身を変えたときは
`sw.js` の先頭にある `const CACHE = 'yukyu-vN';` の数字を1つ上げてから Push してください。

## 2. スマホのホーム画面に追加する

### iPhone / iPad（Safari）
1. Safari で上記のURLを開く
2. 下の **共有ボタン**（□に↑）をタップ
3. **「ホーム画面に追加」** → 追加

※ Chrome や他のブラウザではなく **Safari** で行ってください（iOS の仕様です）。

### Android（Chrome）
1. Chrome で上記のURLを開く
2. 右上の **︙** メニュー
3. **「ホーム画面に追加」**／「アプリをインストール」

追加後はアドレスバーのない全画面アプリとして起動し、圏外でも開けます。

## 3. データについて

### このリポジトリに個人データは入っていません

公開リポジトリにするので、勤務実績や有給の取得履歴は **アプリ本体に含めていません**。
誰かがこのリポジトリを見ても、空のアプリのコードが見えるだけです。

データは入力したその端末のブラウザ内にだけ保存され、サーバーにも GitHub にも一切送られません。

### 初回に既存データを取り込む

Excel から移行した Aさん・Bさんのデータは、リポジトリの外に置いてあります。

```
デスクトップ › Claude › 有給管理表 › 有給管理データ.json
```

このファイルを使う端末に渡して（自分宛にメールで送るなど）、アプリの
**設定タブ →「読み込み」**（初回はホーム画面の「バックアップJSONを読み込む」）から取り込んでください。

> このファイルは **GitHub にアップロードしないでください。** 中身が公開されてしまいます。
> `yukyu-app` フォルダの外に置いてあるのはそのためです。

### バックアップ

- 端末をまたいだ共有はされません。スマホとPCで別々に管理されます。
- ブラウザの履歴・サイトデータを消すとアプリのデータも消えます。
- **設定タブ →「書き出し」で定期的にバックアップ**してください。

## 4. 使い方

| タブ | できること |
|---|---|
| **一覧** | 全従業員の残日数・消滅予定・年5日義務を1画面で確認。期限が近い順／残日数順／名前順に並べ替え。カードをタップすると個人画面へ |
| **個人** | 残日数、次に消滅する日数と期限、年5日取得義務の進捗、付与と消化の内訳、管理簿 |
| **記録** | 2つの入力モードがあります。**1日ずつ入力**＝取得日を1件ずつ登録（1日 / 半日 / 任意の日数、日付は直接入力とカレンダーの2通り、未来の日付は「取得予定」として別枠で計算）。**月ごとにまとめて**＝日付を覚えていない過去分を、月ごとの日数だけで登録（各月15日として記録） |
| **出勤** | 月ごとの出勤日数を入力。上の年チップで年を切り替えます（**今年から5年先まで既定で入力可。「＋ 年を追加」でさらに先まで**。予定を入れると、その年までの付与日数が実績ベースで出ます）。「前年から写す」「全月に同じ数字」で一括入力。年ごとの入力状況と付与日数の判定結果も確認できます |
| **設定** | 従業員の追加・削除、入社日、付与日数の手動上書き、データの書き出し／読み込み、テーマ |

### 年次有給休暇管理簿

労働基準法施行規則 第24条の7 により、有給が10日以上付与される労働者については
**「時季・日数・基準日」を記載した管理簿の作成と3年間の保存**が義務づけられています。

- 個人タブの「管理簿を表示する」→ 1人分
- 一覧タブの「全員分を表示」→ 全員分

どちらも **印刷ボタン → プリンタの選択で「PDFとして保存」** を選べばPDFになります。
**CSVボタン**を押すとExcelで開ける形式（年度ごとの集計＋取得時季の明細）で保存できます。

## 5. 計算ルール

- **基準日（付与日）** = 入社日の6ヶ月後、以降1年ごと。月末入社はその月の末日に丸めます。
- **付与日数** = 付与日の直前12ヶ月（初回は直前6ヶ月×2）の出勤日数から「1年間の所定労働日数」を求め、労働基準法第39条の比例付与表で判定。

  | 区分 | 0.5年 | 1.5 | 2.5 | 3.5 | 4.5 | 5.5 | 6.5〜 |
  |---|---|---|---|---|---|---|---|
  | 週5日以上（年217日〜） | 10 | 11 | 12 | 14 | 16 | 18 | 20 |
  | 週4日相当（年169〜216日） | 7 | 8 | 9 | 10 | 12 | 13 | 15 |
  | 週3日相当（年121〜168日） | 5 | 6 | 6 | 8 | 9 | 10 | 11 |
  | 週2日相当（年73〜120日） | 3 | 4 | 4 | 5 | 6 | 6 | 7 |
  | 週1日相当（年48〜72日） | 1 | 2 | 2 | 2 | 3 | 3 | 3 |

- **時効** = 付与日から2年で消滅（労基法 第115条）。
- **消化の順番** = 有効期限の近いもの（古い付与分）から消費。
- **年5日取得義務** = 10日以上付与された場合、付与日から1年以内に5日（労基法 第39条第7項）。

### 反映していないこと
- 就業規則で法定を上回る付与（→ 設定タブの「付与日数の手動調整」で上書きしてください）
- 出勤率8割未満による不付与
- 時間単位年休、計画的付与

最終的な判断は就業規則と実際の労務管理でご確認ください。

## 6. ファイル構成

```
index.html   画面の骨組みとデザイン
core.js      計算ロジック（法令の付与表・時効・消化順）
ui.js        画面の描画と操作
manifest.json PWA の設定（アプリ名・アイコン）
sw.js        オフライン用キャッシュ
icons/       アイコン画像 4種
```

リポジトリの外（アップロードしない）：

```
../有給管理データ.json   Excelから移行した A/Bさんのデータ
```

## 7. 更新するとき

1. ファイルを書き換える
2. `sw.js` の先頭にある

   ```js
   const VERSION = 'v11';
   ```

   の数字を 1 つ上げる（`v7`, `v8` …）
3. `ui.js` の先頭にある

   ```js
   const APP_VERSION = 'v11';
   ```

   も同じ数字に合わせる（設定タブに表示され、更新できたか確認できます）
4. GitHub Desktop で Commit → Push

アプリ本体はネットワーク優先で読み込むので、オンラインなら**開き直すだけで最新になります**。
反映されないときは、設定タブの **「更新を確認する」** を押してください。

### それでも古い画面が出るとき（iPhone のホーム画面アプリ）

1. 設定タブ →「書き出し」でデータをバックアップ
2. アプリをタスクから完全に終了して開き直す
3. それでもダメなら、ホーム画面のアイコンを削除 → Safari でURLを開いて「ホーム画面に追加」し直す
4. 必要なら「読み込み」でバックアップを戻す
