# 有給管理（PWA）

年次有給休暇の **残日数 / 消滅期限 / 付与日数 / 年5日の取得義務** を自動計算し、
管理簿などの帳票まで出せるアプリです。スマホでもPCでも使えます。
サーバー不要の静的サイトなので、GitHub Pages に置くだけで動きます。

---

## 1. GitHub Pages で公開する手順

**このフォルダ（`yukyu-app`）は、すでに Git リポジトリとして初期化・コミット済みです。**
GitHub Desktop に登録するだけで公開できます。

### 初回だけ

1. GitHub Desktop を開く（未導入なら https://desktop.github.com ／ GitHubアカウントでサインイン）
2. メニュー **File → Add local repository...**（Ctrl+O）
3. **Choose...** で次のフォルダを選ぶ

   ```
   C:\Users\lum4g\OneDrive\デスクトップ\Claude\有給管理表\yukyu-app
   ```

4. **Add repository**
5. 画面中央の **Publish repository** をクリック
6. ダイアログで
   - **Name**: `yukyu`（好きな名前でOK）
   - **Keep this code private のチェックを外す** ← 外さないと GitHub Pages が使えません
7. **Publish repository**
8. メニュー **Repository → View on GitHub**（Ctrl+Shift+G）
9. **Settings → Pages → Source: `Deploy from a branch` / Branch: `main` `/ (root)` → Save**
10. 1〜2分待ってページを再読み込みすると、公開URLが出ます

   ```
   https://<ユーザー名>.github.io/yukyu/
   ```

> 公開されるのはアプリのコードだけで、有給のデータは含まれません（下の「3. データについて」を参照）。
> `有給管理データ.json` は `yukyu-app` の外（親フォルダ）にあるので、コミット対象になりません。

### 2回目以降（ファイルを更新したとき）

1. GitHub Desktop を開くと、左の **Changes** に変更されたファイルが出ています
2. 左下の **Summary** に何を変えたかを短く入力
3. **Commit to main**
4. 上部の **Push origin**

数十秒でサイトに反映されます。アプリの中身を変えたときは、下の「7. 更新するとき」にある
3か所のバージョン番号を上げてから Push してください（スマホに古い画面が残らないようにするため）。

## 2. スマホのホーム画面に追加する

### iPhone / iPad（Safari）
1. Safari で上記のURLを開く
2. 下の **共有ボタン**（□に↑）をタップ
3. **「ホーム画面に追加」** → 追加

※ Chrome や他のブラウザではなく **Safari** で行ってください（iOS の仕様です）。

### Android（Chrome）
1. Chrome で上記のURLを開く
2. 右上の **︙** メニュー
3. **「ホーム画面に追加」**／「アプリをインストール」

追加後はアドレスバーのない全画面アプリとして起動し、圏外でも開けます。
PCでは Chrome / Edge のアドレスバー右の「インストール」からアプリとして追加できます。

## 3. データについて

### このリポジトリに個人データは入っていません

公開リポジトリにするので、勤務実績や有給の取得履歴は **アプリ本体に含めていません**。
誰かがこのリポジトリを見ても、空のアプリのコードが見えるだけです。

データは入力したその端末のブラウザ内にだけ保存され、サーバーにも GitHub にも一切送られません。
外部のサービスやフォントの読み込みもしません（数字用のフォントもアプリに同梱しています）。

### 初回に既存データを取り込む

Excel から移行した Aさん・Bさんのデータは、リポジトリの外に置いてあります。

```
デスクトップ › Claude › 有給管理表 › 有給管理データ.json
```

このファイルを使う端末に渡して（自分宛にメールで送るなど）、アプリの
**設定 →「データ」→「読み込み」**（初回は最初の画面の「バックアップJSONを読み込む」）から取り込んでください。

> このファイルは **GitHub にアップロードしないでください。** 中身が公開されてしまいます。
> `yukyu-app` フォルダの外に置いてあるのはそのためです。

### バックアップ

- 端末をまたいだ共有はされません。スマホとPCで別々に管理されます。
- ブラウザの履歴・サイトデータを消すとアプリのデータも消えます。
- **設定 →「データ」→「書き出し」で定期的にバックアップ**してください。
  - パスワードを付けて書き出すと、ファイルが暗号化されます（AES-GCM）。読み込むときに同じパスワードが必要です。**パスワードを忘れると開けません。**
  - 一度も書き出さないまま数日たったときや、前回の書き出しから30日以上たって変更があるときは、ダッシュボードにお知らせが出ます。
- 「消えにくい保存」をオンにすると、ブラウザが容量不足のときに自動でデータを消しにくくなります（ブラウザが対応している場合）。
- 読み込み・消去・従業員の削除・CSV取り込みの直前のデータは1つ控えが残り、「直前のデータに戻す」で戻せます。
- **変更の履歴**（最大120件）から、最近の変更を1件ずつ「元に戻す」こともできます。

### 画面のロック

設定 →「ロック」でパスコードを決めると、開いたときと、一定時間アプリから離れたときにロック画面が出ます。
のぞき見を防ぐためのもので、**データそのものを暗号化するものではありません**（暗号化したいときはパスワード付きの書き出しを使ってください）。
パスコードを忘れたときは、ロック画面の「忘れた」から30秒待つとロックを外せます（データは消えません）。

## 4. 使い方

PCでは左のメニュー、スマホでは下のタブ（一覧・個人・記録・出勤・メニュー）で画面を切り替えます。
スマホの「メニュー」からカレンダー・帳票・設定に進めます。

| 画面 | できること |
|---|---|
| **ダッシュボード（一覧）** | 使える有給の合計・30日以内に消滅する人・年5日の未達・今月の取得・今年度の取得率。従業員の一覧（期限が近い順／残日数順／名前順、退職者の表示）、名前・番号・店舗での検索、店舗・拠点での絞り込み。右側に「要対応」「今週のお休み」「次の付与」 |
| **個人** | 残日数（時間単位の端数は「9日6時間」のように表示）、次に消滅する日と日数、次回付与、取得予定を引いた残り。お知らせ（消滅・年5日・不足など）、月ごとの取得日数のグラフ（表でも見られます）、付与ごとの内訳、今後の付与、管理簿・お知らせ・カレンダー登録のボタン、従業員の情報 |
| **取得の記録** | 上部に「使える有給・予定を引くと・年5日義務」が出て、入力するとその場で更新されます。**1日ずつ**（1日／午前・午後の半休／時間単位※／日数を指定、計画年休の印、メモ）、**期間で**（〇日〜〇日をまとめて。勤務パターンの休みや祝日は除けます）、**月まとめ**（日付を覚えていない分を月ごとの日数で）。記録の検索、タップして直す、削除の「元に戻す」。土日・祝日の記録は確認が出ます（設定で止められます） |
| **出勤日数** | 月ごとの出勤日数を入力（年は今年から5年先まで、「＋ 年を追加」でさらに先まで）。「前年から写す」「全月に同じ数字」「勤務パターンから入れる」。出勤率8割の判定をオンにしたときは「所定労働日数」も入力でき、付与ごとの出勤率と判定結果が出ます |
| **カレンダー** | 月ごとに、誰がいつ休んだか（予定を含む）を表示。日をタップするとその日の一覧。**一斉休暇**（全員や店舗ごとに同じ日をまとめて記録。計画年休の印も付けられます） |
| **帳票・出力** | 年次有給休暇管理簿（表示・印刷・CSV・Excel）、本人へのお知らせ（1人1枚）、年度末の一覧表（基準日を選んで表示・CSV）、有給休暇取得届（記入して印刷／白紙）、カレンダー登録用ファイル（.ics：消滅の期限・年5日の期限・次回付与を30日前に通知） |
| **設定** | 会社（会社名、**複数の会社・事業所の切り替え**）、従業員（追加・編集・削除）、付与のルール、入力の確認、データ（書き出し・読み込み・CSV取り込み）、変更の履歴、表示（テーマ・文字の大きさ）、ロック、使い方ツアー |

※ 時間単位は、設定の「付与のルール」で「時間単位年休を使う」をオンにしたときだけ出ます。

### 従業員ごとに設定できること

氏名・社員番号・店舗／拠点・部署・雇用形態・入社日・退職日、週の所定労働日数（**途中で契約が変わった履歴**も登録可）、
週30時間以上か、1日の所定労働時間（時間単位年休の換算用）、勤務パターン（曜日・祝日）、
育児休業・介護休業・産前産後・業務上の傷病などの**休業・休職の期間**（出勤率8割の判定で「出勤とみなす／全労働日から除く」）、
アプリを使い始める前の**移行時の残日数**、付与日数の手動調整。

### CSV での取り込み

設定 →「データ」から、**出勤日数・従業員名簿・移行時の残日数** をCSVで取り込めます。
それぞれ「ひな形」をダウンロードして、Excel で埋めてから取り込んでください。取り込む前に内容の確認画面が出ます。

### 年次有給休暇管理簿

労働基準法施行規則 第24条の7 により、有給が10日以上付与される労働者については
**「時季・日数・基準日」を記載した管理簿の作成**と、**期間中と満了後5年間（当分の間は3年間）の保存**が義務づけられています。

- 個人画面の「管理簿」→ 1人分
- ダッシュボードの「全員分を表示」→ 全員分
- 帳票・出力の「表示・印刷」→ 全員分（店舗・拠点で絞り込んでいるときは、その店舗の人）

**印刷ボタン → プリンタの選択で「PDFとして保存」** を選べばPDFになります。
**CSV／Excel** ボタンで、年度ごとの集計＋取得時季の明細を保存できます。

## 5. 計算ルール

- **基準日（付与日）** = 入社日の6ヶ月後、以降1年ごと。月末入社はその月の末日に丸めます。
  - 設定で、初回付与までの月数（0〜6ヶ月）と、**統一付与日**（例：毎年4月1日にそろえる）を指定できます。統一付与日は「適用開始日」以降の付与から使います。
- **付与日数** = 付与日の直前12ヶ月（初回は直前6ヶ月×2）の出勤日数から「1年間の所定労働日数」を求め、労働基準法第39条の比例付与表で判定。出勤日数が未入力の期間は、週の所定労働日数から判定します。
  - 従業員ごとに「契約の週所定日数で判定」も選べます（契約の変更履歴があれば、付与日時点の契約で判定）。
  - 週30時間以上の人は常に通常の付与です。

  | 区分 | 0.5年 | 1.5 | 2.5 | 3.5 | 4.5 | 5.5 | 6.5〜 |
  |---|---|---|---|---|---|---|---|
  | 週5日以上（年217日〜） | 10 | 11 | 12 | 14 | 16 | 18 | 20 |
  | 週4日相当（年169〜216日） | 7 | 8 | 9 | 10 | 12 | 13 | 15 |
  | 週3日相当（年121〜168日） | 5 | 6 | 6 | 8 | 9 | 10 | 11 |
  | 週2日相当（年73〜120日） | 3 | 4 | 4 | 5 | 6 | 6 | 7 |
  | 週1日相当（年48〜72日） | 1 | 2 | 2 | 2 | 3 | 3 | 3 |

  就業規則で法定を上回る日数を付与している場合は、設定の「付与のルール」で**付与表を自社の日数に変更**できます（法定より少ない日数を入れても、法定の日数を使います）。

- **時効** = 付与日から2年で消滅（労基法 第115条）。
- **消化の順番** = 有効期限の近いもの（古い付与分）から消費。
- **半日単位** = 0.5日として数え、年5日の取得義務にも含めます。
- **時間単位**（設定でオン）= 1日の所定労働時間（1時間未満は切り上げ）で日数に換算。年5日分までが上限（設定で変更可）で、**年5日の取得義務には含めません**。
- **計画年休**（計画的付与）= 印を付けて記録できます。年5日の取得義務に含めます。
- **月まとめの記録** = その月の15日の取得として計算。ただし今月分は15日を待たず、入力した日の取得として扱います。
- **年5日取得義務** = 10日以上付与された場合、付与日から1年以内に5日（労基法 第39条第7項）。
  - 付与日を早めて1年の期間が重なるときは、設定で**比例按分**（重なった期間をまとめ、月数÷12×5日）にできます。
- **出勤率8割**（設定でオン）= 所定労働日数を入力した期間について判定し、8割未満の年は付与しません。育児・介護休業、産前産後、業務上の傷病、年休取得日は出勤とみなし、会社都合の休業などは全労働日から除きます。
- **退職日** = 退職日より後の付与はしません。退職時点の残日数を記録し、退職後の残日数は0として扱います（記録と管理簿は残ります）。
- **移行時の残日数** = 移行日（アプリを使い始めた日）時点の付与ごとの残りを入れると、それ以前の記録は残日数の計算に使いません。

新しく加わったルール（統一付与日・付与表の変更・出勤率8割・比例按分・時間単位）は**初期設定ではオフ**です。
オフのままなら、これまでと同じ計算結果になります。

### 反映していないこと
- 本人による申請・上長の承認、複数の端末でのデータ共有、メールなどでの自動通知（サーバーが必要なため）
- 特別休暇（慶弔休暇など）や代休の管理
- 午前と午後で時間数が違う半休（どちらも0.5日として数えます）

最終的な判断は就業規則と実際の労務管理でご確認ください。

## 6. ファイル構成

```
index.html     画面の骨組みとデザイン
holidays.js    日本の祝日（振替休日・国民の休日を含めて計算）
core.js        計算ロジック（付与表・比例付与・時効・消化順・年5日・出勤率・管理簿）
io.js          ファイルの入出力（CSV・Excel・カレンダー・暗号化）
ui.js          画面の共通部分と操作
ui-dash.js     ダッシュボード・個人・カレンダー
ui-forms.js    取得の記録・出勤日数・従業員の編集
ui-docs.js     管理簿・お知らせ・一覧表・取得届などの帳票
ui-data.js     会社の切り替え・設定・バックアップ・履歴・ロック
manifest.json  PWA の設定（アプリ名・アイコン）
sw.js          オフライン用キャッシュ
icons/         アイコン画像 4種
fonts/         数字用フォント Jost（SIL Open Font License。OFL.txt を同梱）
```

リポジトリの外（アップロードしない）：

```
../有給管理データ.json   Excelから移行した A/Bさんのデータ
```

## 7. 更新するとき

ファイルを書き換えたら、**3か所のバージョンを同じ数字に上げて**から Commit → Push。

| ファイル | 場所 |
|---|---|
| `sw.js` | `const VERSION = 'v17';` |
| `ui.js` | `const APP_VERSION = 'v17';` |
| `index.html` | 末尾の `<script src="….js?v=17">` 8か所（holidays / core / io / ui / ui-dash / ui-forms / ui-docs / ui-data） |

新しいファイルを追加したときは、`sw.js` の `SHELL` の一覧にも加えてください（オフラインで開くため）。

アプリ本体はネットワーク優先で読み込むので、オンラインなら開き直すだけで最新になります。
新しい版が用意できると画面下に「新しい版があります」と出るので、そこから更新してください
（入力中に勝手に読み込み直すことはしません）。

いま動いている版は **設定の一番下**（PCは左メニューの下にも）に出ます。

### それでも古い画面が出るとき

**PC（Chrome / Edge）**

1. `Ctrl + Shift + R`（強制リロード）を2回
2. それでもダメなら `F12` → 上部タブの **Application** → 左の **Service Workers** → **Unregister** → ページを再読み込み

**iPhone のホーム画面アプリ**

1. 設定 →「データ」→「書き出し」でデータをバックアップ
2. アプリをタスクから完全に終了して開き直す
3. それでもダメなら、ホーム画面のアイコンを削除 → Safari でURLを開いて「ホーム画面に追加」し直す
4. 必要なら「読み込み」でバックアップを戻す
